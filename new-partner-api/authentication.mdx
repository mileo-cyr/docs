---
title: "Authentication"
description: "Create machine clients and obtain access tokens for the Cyrisma New Partner API"
---

The New Partner API authenticates with a **machine client**: a `client_id` and `client_secret` pair
that you create and manage yourself. You exchange the pair for a short-lived bearer token, and send
that token on every request.

## Create a machine client

<Info>
  The values shown throughout this documentation are examples only.
</Info>

```bash
curl -fsS -X POST "https://ccnnnnnn.cyrisma.com/ta/v1/partners/machine-clients" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "display_name": "Reporting integration",
    "scopes": ["pulse.read"],
    "inherits": true
  }'
```

```json
{
  "client_id": "pc_9f2c41d8a7b34e10",
  "client_secret": "pcs_1a2b3c4d5e6f7g8h9i0j",
  "display_name": "Reporting integration",
  "scopes": ["pulse.read"],
  "roles": [],
  "inherits": true,
  "status": "active",
  "created_at": "2026-08-30T09:14:22Z"
}
```

<Warning>
  `client_secret` is returned only in this response and cannot be retrieved afterwards. Store it
  before continuing. If a secret is lost, revoke the machine client and create a new one; the
  replacement has a new `client_id`.
</Warning>

### Fields

| Field | Description |
| --- | --- |
| `display_name` | Label shown when listing credentials. |
| `scopes` | Permissions the credential may request. See [Scopes](#scopes). |
| `roles` | Optional role names. Leave empty unless directed otherwise. |
| `inherits` | Whether the credential reaches tenants beneath the one it is created under. Set `true` for a credential that covers your organization and all tenants under it. Set `false` to restrict it to that one tenant. |

### List and revoke

```bash
curl -fsS "https://ccnnnnnn.cyrisma.com/ta/v1/partners/machine-clients" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

curl -fsS -X DELETE "https://ccnnnnnn.cyrisma.com/ta/v1/partners/machine-clients/pc_9f2c41d8a7b34e10" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Listing returns `client_id` and metadata. It never returns the secret. Revoking is immediate and
cannot be undone.

## Request an access token

```bash
curl -fsS -X POST "https://ccnnnnnn.cyrisma.com/ta/v1/auth/client-token" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "pc_9f2c41d8a7b34e10",
    "client_secret": "pcs_1a2b3c4d5e6f7g8h9i0j",
    "requested_scopes": ["pulse.read"]
  }'
```

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "expires_at": "2026-08-30T10:14:22Z",
  "subject_type": "machine_client"
}
```

Tokens are valid for 60 minutes. Request a new token when the current one expires; there is no
refresh token. Invalid credentials return `401`.

## Send the token

```bash
curl -fsS \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://ccnnnnnn.cyrisma.com/app/pulse/v1/partner/vulnerabilities/cves?page_size=100"
```

## Scopes

| Scope | Grants |
| --- | --- |
| `pulse.read` | Reading reporting data, tenants, and usage. |
| `pulse.write` | Provisioning tenants, managing users, and changing authentication policy. |

Request only the scopes an integration needs. A token requesting a scope the machine client does not
hold is rejected.

## Tenant scope

Every request is restricted to the tenants the credential is authorized for: the tenant it was
created under, plus that tenant's descendants when `inherits` is `true`.

Narrow a request with `tenant_ids`, a comma-separated list of tenant identifiers. Add
`include_descendants=true` to widen each identifier to that tenant and everything beneath it.

```bash
curl -fsS \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://ccnnnnnn.cyrisma.com/app/pulse/v1/partner/vulnerabilities/cves?tenant_ids=$TENANT_ID&include_descendants=true"
```

Requesting a tenant outside the authorized set returns `403`, whether or not that tenant exists.

Use `GET /app/pulse/v1/partner/tenants` to list the tenants a credential can reach.
